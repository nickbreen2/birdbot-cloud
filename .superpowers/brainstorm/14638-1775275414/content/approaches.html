How should the dropdown behave?

Three ways to structure the user menu interaction in the sidebar.

A ★

Floating popup above the card Recommended

Clicking the user card at the bottom opens a small floating panel that pops up above it. Clean, familiar pattern (like VS Code, Linear, Vercel). Dropdown closes when you click outside or pick an option.

Pros

  • Familiar UX pattern
  • Doesn't change sidebar layout
  • Easy to extend later

Cons

  • Needs click-outside handler
B

Accordion inside the sidebar

Clicking the user card expands a section inline within the sidebar — no floating element, menu items appear below the card and push other content up.

Pros

  • No z-index / overflow issues
  • Stays within sidebar bounds

Cons

  • Can feel cramped at bottom
  • Less polished / less expected
C

Full-width sidebar overlay

Clicking opens a new "layer" inside the sidebar that slides in — similar to how some apps replace the sidebar content with a menu. Full sidebar width, feels like a sub-panel.

Pros

  • Lots of space for content
  • No floating element complexity

Cons

  • Hides nav while open
  • More animation/state work
  • Overkill for 3 menu items
